## Log (newest first)

### 2026-08-05: Before re-justifying a structural ad-group split as "too many keywords," check whether keyword count actually predicts the QS gap ([Account: Water])
When asked to re-verify a prior split recommendation with more data, don't just restate the original rationale — recompute it. [Account: Water]'s Under Sink split was originally framed as "239+ keywords is too broad, that's dragging Quality Score," but a theme-level QS breakdown (Kitchen 38 kws/QS 3.22, Anchor 212 kws/QS 2.97, Faucet-Drinking 22 kws/QS 2.21) showed keyword count doesn't predict QS in this account — a tight 13-keyword sibling ad group (RO) scored worse (QS 2.80) than the 38-keyword Kitchen theme. The split still held, but the real justification became the theme-level QS gap (differentiated copy/relevance), not group size — and the account's overall QS floor is a separate, bigger issue the split won't fix on its own. Always re-derive the "why" from the current data before restating a months-old recommendation, since the original mechanism may not survive scrutiny even when the recommended action still does.

### 2026-08-05: Always build a full-flight cumulative + MoM view spanning every period analyzed, and hold a repeat finding's urgency to its actual trend direction ([Account: Water])
When a client asks to add a new period's data to an account already analyzed in a prior pass, don't report the new period in isolation — recombine it with every earlier period into a cumulative total plus a month-over-month table (split by program/channel where the account reports that way), even though the earlier data lives only in a previously-published report and its original raw export. Recompute the prior period directly from its raw file rather than trusting the old report's prose, both as a cross-check and because it can surface real issues (see below). Critically: when a recommendation from a prior report reappears in the new period's data, check whether the underlying metric is trending better, worse, or flat before deciding how to frame it — "still present" is not the same as "still an emergency." [Account: Water]'s May "add an industrial negative" recommendation was never applied, but the leakage share had already improved from 60%/65% to 52.7%/45.0% of RO clicks/spend on its own; the fix stayed HIGH priority but the framing shifted from "unresolved failure, escalate" to "trending better, this action captures the remaining upside." Similarly, a structural ad-group-split recommendation that hasn't been executed in ~2 months is not evidence of neglect in a B2B media-ops cadence if the underlying keyword count shows steady active management — check for that signal before implying the account team dropped the ball. And hold brand-new findings (an ad group only 3 weeks old) to a MONITOR/LOW action, not an active recommendation, until there's enough data to be confident it isn't noise.

### 2026-08-05: A "position" or similar named metric column can silently change definition between two export pulls of the same report type — verify the exact column header before trending it across periods ([Account: Water])
[Account: Water]'s April–May Google export's rank-proxy column was literally named `Impr. (Top) %` (top-of-page rate); the June–July export's column was `Impr. (Abs. Top) %` (absolute-top-only, a stricter subset). Naively presenting 85%→41% as one trend line would have fabricated an 85%→41% "collapse" that never happened — it was two different metrics with the same rough idea but different definitions across pulls. Before building any cross-period trend table, diff the exact column header text between the two export files, not just the eyeballed column position or a similar-sounding name; if they differ, label each period's number by its own metric name and explicitly footnote that they aren't directly comparable rather than charting them together. This is a distinct trap from the already-documented `Impr. (Top) %` ≠ Impression Share confusion — this one is about the same nominal metric changing definition between pulls, not about misreading one pull's metric.

### 2026-07-09: Quarterly "how did our optimizations perform" wrap-up decks — build around named changes ([Account: Dental] Q2)
When a client asks how specific optimizations performed, build the deck around the NAMED optimizations (what changed, when, before/after) rather than a generic performance recap. Use change-history exports to date optimizations precisely; if no change-history covers the exact window, use the closest adjacent file (a Q1 change-history file can still date a change landing at the Q1/Q2 boundary) and say so plainly rather than leaving it undated. Pair with a full per-platform breakdown slide (spend/clicks/CTR/output) that ladders up to the top-line KPI cards, plus per-campaign detail slides showing top ad groups with labeled screenshot placeholders — this client wants to "get into the details." Also always compute MoM for at least the current quarter, and check `outputs/reports/ppt/` for a prior-quarter deck by name to use as a named benchmark before assuming one doesn't exist; if the exact file the user references is missing, fall back to the closest available real data and say so.

### 2026-07-09: Keyword-opportunity checks must span ALL prior research passes, not just the latest ([Account: Dental] Q2)
When a client asks for new keyword opportunities, build the full set of already-surfaced recommendations from every prior report/audit for the account (not just the most recent), dedupe against the account's active-keyword universe, and only surface genuinely new findings. Explicitly list what was checked and found not worth recommending, not just what to add. This session checked ~15 candidates against 3 prior research passes and a 435-term active universe — only 2 survived. Extends the 2026-06-17 active-keyword-validation entry to cover the account's full research history, not just current live keywords.

### 2026-07-09: Fingerprint a mislabeled Search Term Report hiding inside an ad-level export ([Account: Dental] Q2)
A file can carry BOTH a `Search keyword` column (small distinct count) and a separate `Search term` column (much larger distinct count, differing from the keyword on nearly every row) — that is a Search Term Report regardless of filename or apparent ad-level schema, so its clicks/spend are likely understated by the account's documented 40-70% even if a prior session used it at face value. Check for this dual-column signature before trusting an "ad-level" export's totals; it extends the standing "clicks/spend come from the performance report, never the ST report" rule with a concrete detection test.

### 2026-07-09: Re-verify a carried-forward appendix against its own source material ([Account: Dental] Q2)
When a client asks to carry a slide/recommendation forward from a prior deck into a new appendix "so they don't forget," don't copy it verbatim — re-check it against the original source. A carried-forward brand-campaign keyword table blended in a cluster the source workbook had explicitly labeled "out of scope" (a separate orthodontics line), which would have inverted the recommendation if not caveated.

### 2026-07-09: Never assume a non-Search Google Ads channel (Display, etc.) shares the Search export's period coverage — check each file's own header independently ([Account: Dental] Q2)
A Q2 "final" wrap-up had Search campaign reports genuinely covering the full Apr 1 – Jun 30 window, but the Display exports for the same account only covered Apr 1 – May 24 despite living alongside the full-quarter Search files and being used in a "Q2 final" deck. Verify period coverage PER CHANNEL, per file — one channel's export being complete says nothing about another's. Flag any channel whose export doesn't match the deck's stated period explicitly, rather than assuming client-supplied files are uniformly scoped.

### 2026-07-08: When conversions are sparse and concentrated, call out concentration + tracking coverage on the exec slide ([Account: MedSurg])
On a sparse-conversion account, don't just report the total conversion count — name which campaign/theme concentrates them ([Account: MedSurg]: 43 quarter conversions, ~25 on Brand_[Former Parent Co] [Product Line B] alone, tied to the [Product Line B] relaunch) and call out the sibling program with near-zero conversions as click/rank-optimized rather than CPA-optimized (Skin & Nasal: 3 conversions all quarter). Also flag when only a single conversion action is tracked account-wide (e.g. one lead-form action) as a likely undercount of true lead volume, and turn broadening conversion tracking into an explicit next-quarter ask rather than a passing caveat — this is the standard framing for any lead-gen search account with thin Google-side conversion data (see the existing "frame sparse-conversion B2B as demand-capture" entry below).

### 2026-07-08: Keyword dedup must also check change history, not just the performance export's Search-keyword column ([Account: MedSurg], tooling fix)
The active-keyword dedup check built its active set only from the performance export's `Search keyword` column, which only lists keywords with impressions in the current window — so a keyword added before the window with zero impressions all quarter was invisible and got wrongly recommended as net-new ([Account: MedSurg]: `core temperature monitoring`, `surgical site infection prevention`). This is a tooling gap, not something to punt to the client: `scripts/qa_lint.py`'s `lint_keyword_dedup` now also parses a change-history export's "keyword added" entries and unions them into the active set (pass the change-history CSV as an extra `--raw`). Always request and lint against the change-history export when validating keyword-ADD recommendations, not just the performance report — that is what the dedup check and this skill's Section 6b exist to prevent.

### 2026-07-08: Check change history for a fresh end-date extension on fixed-term/SOW campaigns every refresh ([Account: MedSurg])
A Google Ads campaign scheduled as a fixed-term SOW engagement can have a change-history-logged end date that lapses between refreshes. Check the change history for a fresh extension at the start of every refresh. An unconfirmed extension past an already-passed end date is worth verifying with the client, but don't escalate it as an urgent "may already be paused" alarm before asking — a quarterly-SOW account may simply be mid-renewal on a cadence the client already has in hand. On [Account: MedSurg] all 5 in-scope campaigns had their end dates moved Mar 31 to Jun 30, 2026 on Apr 27, with no further extension logged through Jul 7; this was first flagged as the #1 "Now" action, but the client confirmed it was the routine quarterly renewal, already handled.

### 2026-07-08: A scoping fix in one report does not fix the same bug in a sibling report ([Account: MedSurg])
Fixing the whole-account-vs-in-scope-campaigns scoping bug for one deliverable (search_audit) does not mean a sibling deliverable (ad_copy_audit) used the same corrected file; each report's data source needs its own independent verification. [Account: MedSurg]'s 2026-06-17 run fixed the scoping bug for spend/click totals, but that session's ad_copy_audit "display paths resolved" claim had been computed against an unfiltered 52-ad-group whole-account export and stayed wrong (15 of 31 ad groups still missing Path 2) until the 2026-07-08 refresh recomputed it against the correctly 5-campaign-scoped file. ### 2026-07-08: A client-confirmed "just added" keyword may not yet be in the export's active-keyword set

### 2026-07-08: Tally the embedded keyword count across ALL matching change-history rows, not just recognizable examples ([Account: MedTech] Q2, qa-reviewer catch)
When summarizing a "N keywords paused/added" change-history event, sum the keyword-count number in each matching row's change block across every row for that date/event. ### 2026-07-08: Despace CJK keywords before dedup checks, not just lowercase ([Account: MedTech] Q2)
The Search Terms export tokenizes Japanese queries with inter-word spaces (`診断 テスト`) that the keyword performance export's `Search keyword` column does not use (`診断テスト`), so a lowercase-only net-new check falsely flagged 2 high-impression already-active Japanese keywords as new candidates. Strip all whitespace, in addition to lowercasing, from both the active-keyword set and candidate search terms before comparing. This extends the existing keyword-dedup discipline (previously validated on Latin-script terms only) to CJK scripts.

### 2026-06-22: Maximize Clicks = daily-budget-only pacing; never recommend bid moves ([Account: MOEM], user correction)
When a Google Search campaign runs Maximize Clicks, the ONLY pacing lever the client can adjust is the DAILY BUDGET. There is no manual bid up/down, and the optional Max-CPC bid limit is NOT a lever to recommend either. Never write "raise the bid limit / ease daily caps," "bid up/down," or "lift Max CPC"; frame all headroom/pacing deployment as "increase the daily budget" and set the action-CSV recommendation type to `INCREASE_DAILY_BUDGET` (never `ADJUST_BID_UP` / `RAISE_BIDS_FOR_RANK`). Client quote: "we can only update daily budgets for pacing." This corrects the prior [Account: MOEM]/[Account: IWFB] "raise the bid limit" phrasing.

### 2026-06-17: Validate every keyword ADD against the active keyword set — never re-add a live keyword ([Account: MedSurg], Codex PR #34)

## Standing preferences (apply every run)

- **Reconciliation job.** Cross-check every uploaded file against the others on every pass (Search Terms vs the active keyword set vs the performance / Impression-Share / conversion reports). Never characterize, pause, narrow, or consolidate a keyword or ad group from one report alone; look at what it actually captures first.
- **Clicks and spend come from the performance report, never the Search Terms Report.** The ST report only includes terms above Google's threshold, so it undercounts; a report figure higher than the ST sum is expected, not a mismatch. Search-term exports may arrive metric-free (coverage only), so treat absent Clicks/Cost there as expected. Use the ST report only for coverage, leakage, and match-type, and label any ST-derived figure (branded-query signal, keyword-add volumes) as an estimate.
- **Branded-gap default.** A low-performing or dead-looking broad keyword or ad group is often a brand-query catch-all; quantify the brand share and stand up a [Client] branded ad group to capture it before pausing.
- **Broad match dominance.** Broad match consistently dominates spend (80%-plus) at higher CPC than phrase or exact; expect this as the default structural issue to flag.
- **Never blend CAD and USD.** Label currency in every cross-market summary. The user may explicitly override the no-blend rule for a blended view (for example CAD to USD at 0.73); when they do, footnote every converted figure per table.
- **Pacing framing.** Frame pacing against the run-rate plan to-date, not a single-month cap, and pair the variance with a forward action (what the headroom funds).
- **Do not name "DataForSEO" in any output (PPT, CSV, report).** Frame search-volume enrichment as "our keyword research." Keep to rate-limit discipline (500 keywords per request or fewer, 6 requests per minute or fewer, one batched call).
- **Exec-deck conventions.** Lead with the conversion or lead story first (user reorder preference). Single-RSA and empty-display-path findings are agency-side housekeeping (appendix only) unless there is a structural blocker.
